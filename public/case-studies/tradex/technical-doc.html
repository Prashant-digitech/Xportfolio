2. Executive Summary & Design Challenge

Retail financial trading in active segments (equity intraday, options, futures) requires millisecond-accurate execution paired with immediate layout context mapping. Traditional brokers present disjointed workspaces: charts, order books, compliance limits, and trade journaling systems reside in disconnected panels.

The Design Challenge

Our core task was to architect a unified, high-performance desktop framework that bridges analysis, compliance limits, execution speed, and database logging under a single workspace. This report covers the frontend React grid system, the state slicing architecture, local server websocket gateways, and usability statistics.

3. User Research & Behavioral Insights

We conducted structured behavioral surveys and interview sessions with 15 active Indian day traders.

Key Insights:

  • Friction Point 1 (Latency): Standard platforms have order entry delays of up to 500ms, causing price slippage during trends.
  • Friction Point 2 (Safety breaches): 64% of interviewed traders admitted to breach of daily drawdown rules due to emotional trading.
  • Friction Point 3 (Manual logging): Traders write journals manually in Excel, which leads to gaps in tracking trade logs.

The User Persona: Day Trader Sandeep

Sandeep requires high-speed charting overlays and automatic order validations to block bad trades when daily limits are breached.

6. Core Functional Modules - Part 1

TradeX Pro X divides functional features into isolated React component modules.

A. Watchlist Widget

Provides real-time price lists with sparklines showing 1-hour trend directions for active NSE tickers.

B. Charting Widget (Lightweight-Charts)

Renders high-frequency candlestick feeds with volume bars, indicator lines, and target markers.

C. Technical Indicators Panel

Calculates and displays indicator overlays (MACD, RSI, EMA crosses) next to the chart workspace.

6. Functional Modules - Part 1 Page 6

7. Core Functional Modules - Part 2

The core of the execution panel focuses on order submission depth and strict risk guardrails.

A. Order Book Depth

Streams the top 5 bids and asks directly from the broker WebSocket to identify liquidity support.

B. Risk & Drawdown Guardrails

Zustand stores evaluate order details against safety thresholds before sending requests. If a breach is detected, the button controls lock:

IF (orderValue > maxOrderValue OR dailyDrawdown > maxDailyDrawdown) { LockButtons(); DisplayAlert("Safety Limits Breached"); }

8. Core Functional Modules - Part 3

Our intelligence modules automate logging and provide context-aware trade coaching.

A. Automated Trade Journal

Saves trade records to local storage database, capturing technical indicator states at the exact timestamp of execution.

B. AI Copilot Engine

Uses RAG (Retrieval-Augmented Generation) on local embeddings to evaluate trade decisions, outputting constructive performance feedback.

9. Backend Launcher & API Orchestration

The local Node backend (launcher/launcher.js) manages authentication, database migrations, and broker links.

AngelOne SmartAPI WebSocket Client

Subscribes to live feeds and routes incoming ticks to all connected frontend clients via a local server WebSocket on port 8080.

Security Helper Integration

Includes token-bucket rate limiters and payload validators to prevent malicious injections or overload loops in local client requests.
